# Database Rules

## Access Patterns

- All Supabase and Prisma calls must live exclusively in `lib/server/services/`.
- API routes call `lib/server/services/` functions — they never call Prisma or Supabase directly.
- Client components must never import from `lib/server/` — route data through API routes and TanStack Query.

## Prisma

- The Prisma singleton lives in `lib/prisma.ts`. Import from there — never instantiate a new `PrismaClient`.
- Never import from `lib/generated/` directly. Use the re-exports in `lib/shared/generated/` or the Prisma singleton.
- Treat `lib/generated/` as read-only — it is auto-generated by `prisma generate`.

## Supabase

- The Supabase client singleton lives in `lib/supabase.ts`.
- Always rely on RLS policies for row-level access control — do not replicate auth checks in application code.
- For real-time subscriptions, use the Supabase Realtime client from `lib/supabase.ts`.

## Schema Changes

- Schema decisions are documented in `docs/03_DATABASE.md`. Verify alignment before making changes.
- Never invent schema fields not described in `/docs`. If a field is missing, flag it and ask.
